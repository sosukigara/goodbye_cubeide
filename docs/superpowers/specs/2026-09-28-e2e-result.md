# 2026-09-28 — E2E 検証結果: sidebar 変数名が空欄だった不具合

## 症状

スクリーンショットSlotsの STM32 サイドバーで、全 324 行の `変数` 列が**空白**だった。
`値` 列だけが更新され、名前列为常に空だった。

## 真因（実測）

`src/panels/sidebar.ts` の `buildTree` が **リゾルバが実出力する形と違っていた**。

実 resolver（`scripts/elf_resolve.py --all-members`、`build-ext/unit_omni3.elf`）の計測値:

- 葉ノード **327** 個
- うち `name` にドットを含むもの: **0**（`name` は**末尾セグメントのみ**、`loop_hz` / `loop_count`）
- 各ノードは `path` に**完全ドット区切りパス**を持つ（`sys.loop_hz`）

.sidebar 側は `name` にパスupportedだと仮定し、
`parentPath + '.' + mm` で再構成していた。`sys` の葉で `name='loop_hz'` のため
`sys..loop_hz`（空セグメント）になり|labelSegment 抽出が失敗 → 空欄。

`systematic-debugging` 5step:
Reproduce（スクリーンショット）→ Isolate（`buildTree` の `typeName`/label パス）→
Hypothesize（`name` が末尾セグメントなのでは？）→ Fix（`path` を優先し、
無ければ再構成）→ Re-verify（下記実測）。

## 修正

1. `path` があればそれを正とする。無ければ従来どおり `parentPath + '.' + nm`。
   これで `name`/`path` の**どちらの形でも**破綻しない。
2. 葉ラベルは「末尾セグメント（`name` の最終 `.` 以降）＋親 type 名」。
   兄弟の `name` には必ずドットが入るので一意。
3. 空文字列を**throw** する（黙って空欄にしない）。

## テスト

`tests/sidebar-ui.test.ts` に**実測同形（327 葉・大半が `struct <anonymous>`）のフィクスチャ**を追加。

ただし**空テストではない**：既存のフィクスチャは全 type に名前alentがあり `path` が
無かったため、実際の形（path あり・name は末尾セグメント）を再現できていなかった。
以前のフィクスチャで回すと新テストは green になる（= 旧コードでも通る）ことを
**mutation check で確認**し、実際の形にしてから赤くなることを確認した。

- 「全327行の名前が空でない」
- 「data-name に…完整パスが載る」
- 「ノード自身の `path` が再構成より優先される」

## 副次的な CSS 修正（実測で発見）

- `table-layout:fixed` では**列幅は第1行（`thead` の `th`）だけで決まる**。
  `td.v` / `td.o` に幅を宣言しても効かず、均等配分（100/100/44）になっていた。
  → 幅を `th` に移し、`td` にも同じ値を宣言（片方だけではバグに見えるため）。
- `<input>` に `box-sizing:border-box` が無く、`width:100%` + padding + border で
  14px はみ出し → body が 4px 横スクロール。border-box を追加。
- インデントを `6 + depth*12` から `6 + min(depth,4)*8` に。
  深い葉で名前列が 42px 食われていた。
- `td.v` にも `text-overflow:ellipsis` を付与した。**理由**: 値セルは
  `table.live td{overflow:hidden}` の対象であり、ellipsis が無いと列幅を超えて
  値が末尾を黙って切り、**別の数値として読まれる**。実測では 10 文字 hex
  `0xbf800000` は 11.96px monospace で `scrollW 80 == clientW 80` と収まる
  （clipped なし）ので、この追加は現状の防護であって実害の修正ではない。
- 葉ラベルの取得元を `name` から `path` の末尾セグメントに統一。
  resolver が `name` にフルパスを返しても 150px 列を潰さない。

## 配列ノード（実測で発見した 2 つ目の欠陥）

実 ELF の計測: **葉ノード 327 個だがシンボルは 324 個**。差の 3 件は配列だった。

- `periph.fdcan` — `struct <anonymous>[3]`
- `periph.dji_current.target_current_a` — `float[4]`
- `periph.dji_current.now_current_a` — `float[4]`

sidecar はスカラーしか解決しないため、この 3 行は**永久に値が入らない**まま
描画され、さらに `rec.leaves` に混ざってグループの分母を偽っていた
（「3/327 監視」の 327 は到達不能）。_catalog からは消さずに_
「監視対象外」と明示し、葉カウントと操作ボタンから外すようにした。

実測: グループ表示が `3/327 監視` → **`3/324 監視`** に一致。

## テストの削除（6件）

`tests/sidebar.test.ts` の `describe("live variable rows")` 3件と
`describe("live table layout")` 3件を削除した。いずれも
`SIDEBAR_SCRIPT` の**ソース文字列**を正規表現で照合するもので
（`/c\[0\]\.textContent\s*=\s*s\.name/`、`td\.v\{[^}]*width:\d+px`）、
実装の書き方にしか依存しない。変数名を `leafName` に変えただけで落ちる。
同じ意図は挙動テストで担保している。件数は 73 → 67（その後 68）。
