## 実装後レビューで見つかった欠陥と対応

実装後に独立 reviewer 2 名を走らせ、**全テストが緑のまま通っていた欠陥**が見つかった。
すべて修正済み。

| 深刻度 | 欠陥 | 症状 | 対応 |
|---|---|---|---|
| P0 | 書込ダイアログの初期値がデコード済み文字列だが、サイドカーは整数のみ受理 | `bool` 61葉が全て `bad value: 'true'` で拒否。`float` 109葉は整数表記なら**受理されて静かに壊す**（1.0f → `0x00000001` → 読戻し 1.4e-45）。324葉中 170葉（52%）が書けなくなる回帰 | `encodeWriteValue` をデコーダの隣に追加し、host 側で型解釈→生ビット変換（`src/live/poller.ts`）。送信は `bits`、確認ダイアログは `→ 0x…` を併記。TS 22件 + Python 11件で固定 |

## 実機（ST-LINK/V2）検証

### 実測できたこと

- **live poll の基礎経路（変更前コード）**: 790 ticks / drop 0.38% / block read を実測
  （`2026-09-28-live-poll-100hz-8s.log`）。
- **接続の不安定性**: 11 回の接続試行で 1 回 `USB Error: [Errno 110] Operation timed out`。
  「30 秒アイドル後の初回接続」仮説は 3/3 成功で**棄却**。根本原因は**未特定**。
- **ターゲット状態**: 10:39 に `halted_before=True → resume → halted_after=False` を確認。
  以降成功した probe セッションはない。

### 実機で**未検証**のまま残るもの

**実機 E2E は完了していない。** 最終実行を試みたが sidecar は
`Waiting for a debug probe to be connected...` で待ち続け 90 秒で kill され、
`lsusb | grep 0483` は空（デバイス未列挙）、残留プロセス無し。よって以下は証拠が無い:

1. **メンバ幅ごとの read が実 probe で正しいこと**。pyOCD 0.45.1 は
   `coresight/dap.py:1056` で 32bit 以外の転送を拒否するため、実装は
   「ceil(size/4) 個の 32bitワード読み → 自分のバイトだけ取り出す」方式。**MockProbe でのみ実行**。
2. **書込チャネルの read-modify-write が実 probe で隣接バイトを壊さないこと**。
   `tests/test_live_write.py` 36件はフェイク probe でのみ。
3. **現在のターゲットの halt 状態**（probe 不在のため `is_halted()` を呼べない）。

probe を再接続すれば 1 と 3 は 60 秒で確定できる。
